## 1. 两个可独立交付的阶段

**阶段 A：无音频服务的工程闭环。** 完成预留适配器、配置状态、人工文本导入和真实分析层；显式 fixture 只用于验证处理逻辑。业务可拿人工校对文本检查结构、标签与前三秒展示。不能宣布自动语音识别或完整音视频链路验收通过。

**阶段 B：真实 ASR 接入与业务验证。** 首个供应商确定为阿里云百炼 `qwen-audio-3.1-asr-flash-filetrans`。供应商适配器、受控公网媒体传输、真实转写、对齐、C10/C20/C30 音画融合和三条素材回归已完成；业务语义评审仍待进行。供应商返回无语音错误码时已标准化为 `no_speech`，不伪造词级时间。具体步骤见 [真实 ASR 接入计划](ASR-INTEGRATION-PLAN.md)。

## 4. 实施顺序与每步完成定义

### P1

先验证当前 Windows / Linux 的 FFmpeg 与 FFprobe 来源，确定音轨时间映射。实现任务 / capabilities 后，无密钥启动也能显示“未接入”；无音轨有独立业务结果。先用本地生成的非真实音频测试探测，不发送外部接口。

### P2

先实现纯文本和带时间 JSON，再加 SRT 解析。通过超界、重叠、空段、Unicode 与来源检查后接入页面。fixture 通过显式开发配置选择，默认关闭；普通导入只能得到 manual。

### P3

先跑“人工校对文本 → 结构标签”的最小切片，再接入视觉证据与前三秒。用跨 3 秒边界、全文含优惠但前三秒无优惠的样本检查请求级隔离。通过验证后生成完整报告，不提前追求大量标签或复杂排版。

### P4

把报告做成一张简洁卡片，证据按需展开。确认等待、局部成功、跳过、失败有不同文案；标签筛选与分页不可隐藏第 21 条以后的记录。旧 A/B 页面和只读分享的媒体前缀需要回归检查。针对存量视觉结果增加一条显式桥接动作：整理 `visible_text` 为字幕证据后再调用 C10/C20/C30，报告必须标 `manual/subtitle` 并显示非 ASR 局限；旧 A/B 页的逐帧与 B 片段详情默认放入折叠区。

### P5

按 [真实 ASR 接入计划](ASR-INTEGRATION-PLAN.md) 实施：已完成受控公网媒体 URL / WAV 路由、阿里云异步 Provider 和 C10/C20/C30 音画融合；云端回环管理实例已完成 `3D.mp4`、`口播.mp4`、`切片.mp4` 三条回归。记录了实际词 / 句时间戳、语言、usage、远端任务号、无语音错误和报告状态；下一步进入业务语义评审。

### P6

将样本分为提示词调试集和保留评审集。业务逐项查看原文证据、结构作用、标签和开头解释，记录错在转写、视觉、时间还是分析。已有三个视觉样本可做旧功能回归，不能替代新的口播标注集。

## 5. 资源与工作量

- 已有：Python / FastAPI、文件存储、FFmpeg、现有 DeepSeek 接入、本机和阿里云只读演示。
 - 需补充：人工校对口播与字幕样本；业务标签和评分口径。
- 采用云 API 时服务器只做提取、调度与存储，不要求专用 GPU。音频按供应商格式临时保存，成功 / 失败记录与原文留存规则在实际接入时确定。
- P1–P4 初步估计 3–5 个开发工作日；P5 在凭据和样本齐备后约 1–2 日；P6 另需业务评审时间。估算依赖环境、供应商和范围，不是交付承诺。
- 保持单重任务并发；千条批量能力和更长视频暂不纳入上述工时。

## 6. 发布与回滚

1. 本地完成阶段 A 后，只能发布为“人工文本驱动的分析 POC / ASR 未接入”。
2. 完成阶段 B 与相应验收后，才标“自动音频转写已接入”。
3. 分享环境保持只读，迁移已完成结果；复制配置时不携带本地密钥。未来是否允许他人上传运行单独决定。
4. 发布前备份代码、运行时文档和任务数据；验证新目录对服务用户可读写，启动不会覆盖历史。
5. 重启会中断进程内任务，发布时先确认没有正在执行的任务；重启后的未完成任务记录为 interrupted。
6. 回滚应用和文档版本，保留新数据。旧应用应忽略独立的新目录，不能用旧 Schema 校验或覆盖新报告。
